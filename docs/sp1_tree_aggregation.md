# SP1 Hierarchical Round Aggregation

This path turns an arbitrary number of ordered `processMessages` and `tally`
compressed proofs into one compressed SP1 round-root proof. Every aggregation
node has a fixed maximum fan-in of five.

It changes proof orchestration, not AMACI protocol semantics. Every base proof
is still generated by `amaci-proof-sp1-program`; recursive nodes verify those
proofs and enforce the same commitment linkage between batches.

## Tree Shape

The scheduler builds two independent ordered trees:

```text
processMessages base proofs -> groups of <= 5 -> ... -> processMessages root
tally base proofs           -> groups of <= 5 -> ... -> tally root

processDeactivate base proof --+
addNewKey base proof -----------+-> final round-root proof
processMessages root -----------+
tally root ---------------------+
```

At each non-final level, every node verifies between one and five proofs. If a
level has more than five nodes, its outputs are grouped by five again. For
example, 26 ordered child proofs produce `6 + 2 + 1 = 9` recursive stage nodes.
The final round node always verifies exactly four children.

The host processes groups serially and loads at most five child proofs at a
time. This bounds scheduler-side proof memory by the fan-in. SP1's prover still
needs its normal per-node proving memory, and total proving work remains
linear in the number of recursive nodes.

## Linkage Rules

Process-message leaf nodes reuse the base aggregate checks:

- shared packed parameters, coordinator key hash, deactivation commitment and
  poll ID;
- previous `batch_end_hash` equals next `batch_start_hash`;
- previous new state commitment equals next current state commitment.

Tally leaf nodes require:

- consecutive batch numbers;
- one shared state commitment;
- previous new tally commitment equals next current tally commitment.

Internal nodes additionally require all direct children to have the same tree
level, stage and program identity. They preserve the first/last commitments,
sum the base leaf counts and commit a domain-separated SHA-256 subtree root.

The final round root verifies and links:

- `processDeactivate.new_deactivate_root == addNewKey.deactivate_root`;
- coordinator key hash and poll ID across the base and process-message proofs;
- final process-message state commitment to the tally state commitment;
- tally coverage starts at batch zero and is consecutive;
- the exact process-message, tally and total base-proof counts.

## Program Identity

Every V2 tree public output starts with `AMACITR2` and commits both:

- the base AMACI SP1 program vkey digest;
- the recursive tree SP1 program vkey digest.

The recursive guest compares each supplied child vkey digest with the expected
base/tree identity before verifying the child. The CosmWasm contract pins at
instantiate time:

- the compressed tree verifier key hash;
- both program vkey digests;
- the expected poll ID;
- the expected coordinator public-key hash.

`verify_compressed_round_root` accepts only proof and public values. A caller
cannot provide or replace the vkey in the execute message.

## Code Layout

- `crates/proof-core/src/tree_aggregate.rs`: V2 public-output codec, linkage
  validation, fan-in enforcement and round-root construction.
- `crates/proof-sp1-tree-program/src/main.rs`: recursive SP1 guest that verifies
  every child and commits the V2 output.
- `crates/proof-sp1-tree-host/src/main.rs`: serial, resumable, streaming tree
  scheduler and artifact exporter.
- `crates/cosmwasm-amaci-round/src/contract.rs`: fixed-vkey final round-root
  verification and exact round-plan checks.
- `scripts/run_fifteen_signup_sp1_tree.sh`: reproducible 15-signup baseline.

## High-Performance Machine

The tree builder consumes full SP1 SDK compressed proof files, not only the raw
CosmWasm triplets. Generate the nine 15-signup base proofs first with
`scripts/run_fifteen_signup_sp1_aggregation.sh`, or reuse an existing completed
run.

Start the tree build in the background:

```bash
cd ~/zkvm-amaci
mkdir -p logs metrics sp1-proofs

nohup env CARGO_TARGET_DIR=/tmp/zkvm-amaci-sp1-tree-target \
  scripts/run_fifteen_signup_sp1_tree.sh \
  > logs/fifteen-signup-tree-run-$(date +%Y%m%d-%H%M%S).out 2>&1 &
```

Watch progress:

```bash
tail -f $(ls -t logs/sp1-tree-fifteen-signup-*.log \
  logs/fifteen-signup-tree-run-*.out 2>/dev/null | head -1)
```

The scheduler writes each node immediately. Re-running the same command checks
and reuses valid `*.proof.bin` nodes, so an interrupted run resumes rather than
starting the entire tree again.

Completion checks:

```bash
grep -n "tree round build ok\|tree round proof verify ok\|tree round suite ok" \
  $(ls -t logs/sp1-tree-fifteen-signup-*.log | head -1)

cat $(ls -t metrics/sp1-tree-fifteen-signup-*.metrics.txt | head -1)
ls -lh sp1-proofs/fifteen-signup-tree-round-artifacts.tar.gz
```

The archive contains only the final on-chain triplet, decoded public output,
contract configuration, execute message, manifest and metrics. Intermediate
proofs remain on the proving machine for resume and diagnostics.

For another round size, invoke `amaci-proof-sp1-tree-host build-round` directly
and repeat ordered `--process-child` and `--tally-child` arguments as needed.
There is no total-child limit in the scheduler; the per-node limit remains five.

## Local CosmWasm E2E

Copy the archive to the local repository and extract it:

```bash
tar -xzf sp1-proofs/fifteen-signup-tree-round-artifacts.tar.gz -C sp1-proofs
```

Build and run the contract flow:

```bash
npm run build:round-contract

node scripts/run_cosmwasm_round_e2e.mjs \
  --manifest fixtures/round-e2e.fifteen-signup.tree.example.json
```

The runner reads `contract-config.json` into the instantiate message and sends
one `verify_compressed_round_root` execute transaction. A successful query must
show all expected stage counts complete and `verified_proofs = 1`.


Only `proof.bytes` and `public.bin` are sent in the execute transaction. The
vkey and identity values are installed once through `contract-config.json`.

## 50-Signup Benchmark

The recommended multi-group benchmark uses a depth-3 state tree, 50 signup
leaves, 50 messages and 51 final leaves. It produces 10 process-message and 11
tally base proofs, then builds stage trees with widths `[2, 1]` and `[3, 1]`.
See `docs/fifty_signup_tree_e2e.md` for the deterministic vote plan, resumable
proving command, metrics and local aggregate/non-aggregate comparison.
